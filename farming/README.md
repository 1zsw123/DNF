# DNF 70 刷图助手

当前适配特定 70 客户端，支持角色选择、狂战士、通用全技能、刃影、风神和机械之心方案。主流程使用只读坐标、A* 绕障和键盘输入，OCR 负责菜单和库存，HUD 颜色估计血量。

风神和机械师的日常启动、血药设置与恢复方法见 [双角色使用指南](TWO_CHARACTERS.md)。界面可选择血药键和每局人偶，启动前核对游戏角色身份。

新增[通用模式（手动进图）](GENERIC_MODE.md)：手动选择普通清怪副本后接管，不再限于副本下拉框里的地图名称；固定地图方案仍保留。

源码解析见 [ARCHITECTURE.md](ARCHITECTURE.md)。[双机组队设置](dungeon_farm/双机组队使用说明.md)支持大号清怪或小号跟随；用户已反馈双人组队完整通关，换电脑与角色仍应先核对配置。同一电脑不要同时运行旧跟随工具和本助手。

## 本次更新（2026-11-14）

- 狂战士方案改为“技能随便用”，不再等估计冷却（还在冷却的键按了游戏里不会生效）：Q/W/E/R/T/A/S/D 按最久没按过的顺序轮流放，每两个技能之间穿插 2 下普攻 X（怪在普攻距离外则直接接技能）；F/G 增益约每 8 秒补一次；Y 觉醒约每 20 秒尝试，仍保持“按下→等 12 秒→再按”的两段节奏。H 双刀是开关：开打时先按一次 H 打开（界面“双刀已经开着”默认不勾），之后不再按，避免被反复按关；死亡复活后会再开一次。上下判定放宽，减少只走位不出手。
- 更流畅：单人模式清房后只停 0.8 秒确认（原 3.5 秒），走向门口途中出新怪会立刻回头打；觉醒动画等短暂读不到怪物坐标时，原地继续出招而不是干等；H 双刀在进房 1 秒后再按，避免进图过场时按了没生效。运行日志会记下暂停、切窗口、手动操作和读不到坐标的原因，方便排查卡顿。
- 读技能栏冷却（`dungeon_farm/hotbar.py`）：截取右下角 Q–Y / A–H 两排技能格，图标变暗即视为冷却中，直接跳过；按了却没变暗（没放出来）的技能暂停 2.5 秒再试；全部冷却时用普攻 X 补。读数异常（如分辨率或布局不同）会自动退回原来的连按逻辑。每局在 `dungeon_farm/hotbar-sample.png` 保存一张技能栏截图，便于核对位置。
- H 双刀：每次进副本都会重新开（游戏在一局结束后会重置双刀，之前把上一局的“已开”带到下一局导致不按）。进房稳定 1 秒、且 H 图标亮着时先于其它技能单独按；按后看 H 格是否变暗来确认，没确认就补按，最多 3 次。
- 灰色（饱和度为 0）的技能格视为当前不能用（如 W、R），不会去按。
- 通用模式下，带名字但没登记过的人形敌人（APC，如“德魯伊·梅亞”）也会打，已知友方 NPC 仍不打；如果房间只剩这类对象且 25 秒一个都没打掉，就按友方 NPC 处理、本局不再打（记录为 `apc_ignored`）。
- 自动退出重进（界面可关）：卡住 90 秒、找不到通路、小地图超时、复活失败、报错、结算后重进失败等情况，通过游戏菜单点击“返回城镇”（只点识别到的这几个字，绝不点“退出游戏/选择角色”），再按原副本、原难度自动入场。连续失败 3 次才停；疲劳不足或手动停止不会重进。退出时看到的屏幕文字记在 `dungeon_farm/recovery-observation.json`。
- 血药：血量低于 50% 自动使用，两次间隔约 10 秒。狂战士默认每局不限瓶数，可在“血药、人偶与无色”里改为 1/2/3/5/10 瓶；其他方案默认仍为每局 1 瓶。
- 难度可选到王者级、地狱级。只进所选难度、不自动提高；游戏里该难度不可选（未解锁或缺入场道具）时停止，不会进错难度。

此前已实现：

- 阿登高地进图即规划 Boss 路线，全局保存房间图，战斗中提前确定出口；短暂小地图漏检沿用已确认路线。

## 下载与启动

1. 仓库点 **Code → Download ZIP** 并完整解压，进入 `farming` 文件夹。
2. 安装 Windows 64 位 Python 3.12（也兼容安装脚本中的 3.11 入口）。
3. 双击 `install.cmd`，在本目录创建 `.venv` 并安装依赖。
4. 双击 `start.cmd`。首次选择本机游戏目录内的 `DNF.exe`，填写本机角色名，再在助手中点击“读取当前角色”核对实际角色类型。
5. 确认技能和血药设置，在助手选择副本、难度和局数。在已适配城镇入口附近可用“自动入场并开始”，已在副本内则点“开始”。游戏必须保持前台。

默认阿登高地冒险级、1 局；**局数设为 0 才会持续到疲劳不足**。可选普通、冒险、勇士、王者、地狱，不自动提高难度。根特东门、追击歼灭战和阿登高地已有配置；组队请先阅读对应说明。

换电脑运行 `configure.cmd`；换角色在助手中重新读取。配置只保存在本机，不包含登录账号或密码。客户端 SHA256 不匹配时拒绝套用旧坐标结构；通用技能方案不保证适合所有职业的开关、蓄力或召唤机制。

## 操作规则

| 操作 | 当前配置 |
|---|---|
| 普攻 | X |
| 技能 | Q/W/E/R/T/Y/A/S/D/F/G/H |
| 双刀 | 仅狂战士方案：H，启动前确认初始状态 |
| 追踪术 | 仅刃影冷却优先：右、右、空格，每局一次，复活后重开 |
| 帮手 | 角色启用 `entry_helper` 后，每局按一次 4；快捷栏 4 必须放对应人偶 |
| 血药 | 使用该角色配置的 1/2/3 号位，HP 严格低于 50% 才用，两次间隔约 10 秒；每局上限按角色设置（狂战士默认不限，其他默认 1 瓶）；新角色默认关闭 |
| 死亡 | 确认幽灵提示后按 X，最多两次尝试 |
| 无色不足 | 按住 Alt，再按 D 分解 |
| 无色够用 | 按住 Alt，再按 S 卖白装和蓝装 |
| 修理 | 按住 Alt，再按 F |
| 再次挑战 | F10；最后一局维护后不重进 |

无色储备线至少 150，按本轮维护前后的有效基线计算：本轮入场库存减去结算维护前库存，正的净下降量乘 2 再加 30，取与 150 的较大值。没有有效基线则用 150，不再根据技能按键次数推算出上千储备。无色够用优先卖白蓝装备；库存读不准仍走分解分支。出售、分解范围与费用由客户端内置快捷键决定。

F8 暂停/继续、F9 停止，也可用界面按钮。该客户端中热键曾有冲突，优先使用界面。Enter/Esc 会暂停；手动方向键暂时接管，松开后恢复；切到其他窗口停止输入，回到游戏后继续。关闭助手会释放按键。

## 实际范围与限制

- 根特东门曾连续完成两局，战斗耗时分别 241 秒、188 秒；布局不同，不能保证每局三分钟。
- 追击普通级曾从首房已清空处接回后完成 8 次房间访问，197 秒到结算；包含维护约 266 秒。它不是完整入场计时基准。
- 寻路通过实际移动学习碰撞，没有静态全地图通行数据。仍可能绕路或暂停；单人模式记录并忽略未适配对象，但忽略不会消灭可能堵门的敌人。数据不可靠、重进失败会停止或暂停。
- 阿登高地另读小地图房间连接线，整局记住 Boss 路线并按实际过门推进位置；战斗与地图识别并行，真实门数据核对出口。其他地图仍沿用各自探索配置。
- 清场后等待 3.5 秒并在走向出口时持续检查新怪，处理二轮刷怪。
- 刃影冷却来自已核对的技能面板，按发送按键的时刻计时，未直接读取服务器冷却。技能是否真正施放、动作锁和范围仍存在估计误差；HP 来自固定 HUD 颜色估计。
- 自动拾取是当前服务器已有功能，本工具未实现拾取。收益仅记录可确认的金币差，不给未出售材料估价，不宣称追击是所有服务器最高收益图。
- Alt+S 历史自动输入曾没有产生卖装效果，用户后来确认手动有效并修改了本机设置，要求停止按键测试。日志中“输入已发送”不能单独当作售卖成功证据。

## 开发与文件

`dungeon_farm/` 包含运行器、GUI、寻路、战斗、库存和结算状态机，以及离线回归用例。可选执行以下命令，仅运行离线用例，不启动游戏输入：

```powershell
.venv\Scripts\python.exe -m unittest discover -s dungeon_farm -p "test_*.py"
```

回归覆盖全局小地图记忆、绕障、刃影 CD 与每局帮手、角色隔离、血量阈值、组队心跳和维护等待。依赖本机观测文件的可选用例在公开包中会跳过。组队通信测试仅使用本机回环地址，另一台电脑的实际游戏行为仍需双机验证。

运行后会在本机生成 `coordinate-session.json`、GUI 偏好、动作日志、库存读数和异常对象详情。这些数据没有上传；发布包没有游戏客户端、截图、模型训练集、内存转储、登录信息或运行日志。请保留 `.gitignore`。
