# 双机带图首版

本版把坐标跟随接入刷图运行器，同一界面可选单人、大号清怪、小号跟随。两台电脑各运行一份，不在同一电脑并开旧跟随工具和新助手。仍须先在游戏里手动组队并让大号当队长，不代替登录、邀请组队或自动改队长。

当前验证范围：单人阿登高地冒险级已有实机通关；组队逻辑完成本机协议和状态机测试，尚未完成真实双机通关、同步过门及组队 F10 重进验证。不要把单人通关结果当作组队验收。

## 首次配置

1. 两台电脑使用相同版本助手。新电脑先运行 `install.cmd`、`start.cmd`，选择本机客户端。登录角色后，点击“读取当前角色”，核对完整名字与技能方案；不能仅修改旧配置中的名字套用原角色类型。
2. 停止助手后打开“**双机组队设置**”。大号选“大号清怪带队”，小号选“小号跟随”。双方填写对方完整角色名，顺序相反。
3. 大号生成配对码，小号填写相同的码、**大号电脑的局域网 IPv4** 和相同端口（默认 18770）。地址候选可能含虚拟网卡，请使用两台电脑所在同一局域网的地址。不需要公网地址或端口映射。
4. 两边选择相同副本和难度。连续运行时两边局数都设为 0；首次验证也可以都设为 1。小号不自动从城镇走进副本，跟随队长入场；首次建议手动组队入图后启动。
5. 大号先开始，再启动小号；两边游戏保持前台。Windows 若询问网络权限须由用户处理，本工具不修改防火墙。配对码仅保存在各自的 `team-settings.json`，不要放入公开仓库。

## 联动规则

- 大号正常清怪，清场和补刷检查照旧；走近出口时等小号在同房间靠近再推门。失去小号坐标或连接时等待，不用旧位置强行过门。
- 小号进入房间后原地等待，不跟随大号打怪。连续 3.5 秒未发现敌人或未分类对象、读到出口对象，并确认大号在一个明确出口的 200 像素范围内后，才寻路去该真实出口的内侧集合（左右门内侧 60、上下门内侧 45）。目的地由门坐标和朝向计算，不使用大号坐标作终点。门内侧只是对齐点：随后向门外推进，未过门时小幅延伸或调整门线，只有场景变化才确认过门；出现新怪、断线或出口不明确时撤销推进；大号在房间中间或出口有歧义则继续等待。途中出现二轮怪立即停下，换房重新等待。出口对象加清场观察用于判断可集合时机，尚未直接读取门锁状态。
- 小号不使用战斗技能，仍按角色设置低于 50% 才喝药，确认死亡后按 X 复活。新角色默认关闭自动用药，需要先确认对应快捷栏。
- 通关后仅大号按原规则检查库存、卖装或分解、修理。小号不检查背包、不卖装、不分解、不修理、不自动点击弹窗；看到结算重进菜单后报告本轮就绪，只有大号按 F10。小号等待游戏原生组队重进，不自行选择地图。
- 就绪信号必须匹配本次会话和轮次；旧轮次、角色名不符、断线或超过 3 秒的心跳不算就绪。不会跨两台电脑比较进程地址或场景指针。
- 局域网只交换角色名、运行阶段、会话和就绪轮次，不传截图、内存地址、键盘命令或账号信息。坐标仍从各自已核验客户端只读取得。
- 过门、寻路和死亡恢复依然存在地图差异；无路时暂停，等待结算和重进有超时上限。首次需验证本服是否由队长 F10 自动带全队重进；如还要求成员确认，目前会等待或超时，不猜测点击。

## 后续角色名

无需改源代码。等当前单人刷完，再在两台电脑读取各自角色、填写对方名字即可。默认保持单人模式，不会因安装本版自动打开组队连接。

## 模块

`team.py` 读取同场景的指定队友、判断门口集合并生成纯跟随决策；`team_link.py` 同步状态；`team_ui.py` 保存本机配对设置；`runtime.py` 按角色职责分流；`cycle.py` 在维护后实施就绪等待。

本机回归测试包含模拟战斗决策、结算输入隔离，以及仅绑定 `127.0.0.1` 的协议通信测试。无需游戏、无需开放局域网端口即可运行测试。

## 等待原因与当前地图

小号从右上角地图标题选择当前图的敌我分类，不沿用界面旧副本中的友军表。例如追击歼灭战中的背叛者郎克按已核对的类型和名字排除；未知对象仍会阻止清场，并显示具体名字。

跟随集合要求配对心跳有效、大号处于战斗阶段、同场景角色和真实出口可读。大号手动方向键或暂时切出窗口造成的 active 标志变化不再单独阻止集合；断线、停止、维护或结算阶段仍不跨门。结算继续只等待大号重进，不检查库存、不卖装、不修理。
